## 2. 关键约定

这些是踩过坑之后定下来的，改代码前先读一遍：

- **BMI 是派生数据，不落库** —— 由体重 + 身高实时计算；改身高则历史 BMI 全部重算
- **Domain 层不依赖 Android** —— 所有算法是纯函数，可直接 JVM 单测
- **表结构变更必须写 Migration** —— 刻意不提供 `fallbackToDestructiveMigration`
- **数据一律以公制存储** —— 单位切换只是显示层的事
- **颜色、字号、间距不写死** —— 全部走 `ui/theme/` 的 token
- **`tools/*.ps1` 含中文，必须带 UTF-8 BOM** —— PowerShell 5.1 会把无 BOM 的 UTF-8 当 GBK 读，
  中文字节会吞掉后面的字符导致解析报错。**用脚本改完这些文件记得补回 BOM**（已经踩过一次）
- **产物名一律英文** —— 中文文件名在 Windows / adb / 手机文件管理器之间转手会出现编码乱码

## 4. 构建与出包

```bash
./gradlew assembleDebug          # 构建
./gradlew testDebugUnitTest      # 单测（179 个）
./gradlew connectedDebugAndroidTest   # 设备上的 Room 迁移测试（要模拟器/真机）
./gradlew distRelease            # 签名并拷到 dist/WeightDiary-<版本>.apk
```

需要 JDK 17+ 与 Android SDK（compileSdk 36）。

### 4.1 正式包与签名

release 开了 R8（混淆 + 资源压缩）。

> ⚠️ **Room 的生成类是按类名反射查找的**，开 R8 最容易在这一环翻车。
> 每次改混淆规则都要实跑一遍「写入一条记录并读回」再发版。

`distRelease` 需要项目根的 `keystore.properties`（**不在版本库里**）：

```properties
storeFile=keystore/weightdiary-release.jks
storePassword=…
keyAlias=weightdiary
keyPassword=…
```

文件不存在时构建**不会失败**，只是不做签名、出不了可安装的正式包 —— 这样别人 clone 下来照样能跑
`assembleDebug`。

> **密钥库请单独备份。** 丢了就再也发不了「同一个 App」的更新，只能换包名重来。

### 4.2 网络

Gradle 首次构建要从 `services.gradle.org` 与 Maven 仓库拉依赖，网络受限时会超时。
在 `~/.gradle/gradle.properties` 写 `systemProp.https.proxyHost/Port` 设好代理，
或在 Android Studio 的 `Settings → HTTP Proxy` 里配。详见 [03 技术设计 · R2](03-技术设计.md)。

> **代理配置指向一个没在监听的端口时，git 不会回退直连。** 它直接报
> `Failed to connect to github.com:443 over proxy`。此时要显式清空代理走直连：
>
> ```powershell
> git -c http.https://github.com.proxy= -c https.proxy= -c http.proxy= push origin main
> ```
>
> **但直连不一定通。** 实测过同一台机器上 `api.github.com:443` 通、而 `github.com:443`
> 不通：于是 `git push` 失败、API 调用却一切正常 —— 极易误判成 git 本身的问题。
> 直连不通时就只能走代理，先把代理工具起起来。
>
> 判断顺序：**先测端口有没有在监听**（`Get-NetTCPConnection -State Listen`），
> 再决定是绕开代理还是启用代理。两边都试是唯一可靠的确认方式。

## 6. 项目是手工搭建的

没有用 `android create` 或 Android Studio 向导生成 —— 向导产出的目录结构与本项目的约定
（`domain/` 不依赖 Android、`ui/theme/` 集中 token、`docs/` 与代码同仓）不一致，改造的成本比从头写更高。
模块划分、依赖版本、`build.gradle.kts` 都是手写的。

代价是：**新增依赖时要自己查版本兼容**（AGP / Kotlin / KSP / Compose BOM 四者的版本矩阵），升级时也一样。
升级前先跑 `./gradlew testDebugUnitTest`。

## 9. 踩过的环境坑

都不是代码问题，但每次都要花不少时间才能诊断出来。记在这里。

### 9.1 模拟器的 fastboot 快照会降级

**症状**：`adb devices` 显示 `device`，`getprop sys.boot_completed` 也返回 `1`，
但**装不了包**：

```
adb: failed to install app-debug.apk:
  java.lang.IllegalStateException: Cannot access system provider: 'settings'
  before system providers are installed!
```

**根因**：AVD 的 `snapshots/default_boot/` 处于**撕裂状态** —— 内存镜像 `ram.img` 是几天前的，
元数据 `snapshot.pb` 却是刚写的。fastboot 拿旧内存配新元数据，`system_server` 起不来，
但引导标志位已经置上了，于是**所有「是否启动完成」的判断都会骗人**。

**诊断**：别信 `boot_completed`，直接查那个 provider 能不能用：

```powershell
adb -s emulator-5554 shell settings get global device_name
# 正常返回机型名（如 sdk_gphone64_x86_64）
# 降级时报 Cannot access system provider
```

**修复**：删掉快照目录，并把 AVD 改成默认冷启动。

```powershell
Remove-Item "$env:USERPROFILE\.android\avd\<AVD>.avd\snapshots" -Recurse -Force
# 再改 <AVD>.avd\config.ini：
#   fastboot.forceColdBoot=yes
#   fastboot.forceFastBoot=no
```

冷启动实测 **15 秒**，比反复诊断快得多。

> **`-no-snapshot-save` 挡不住它。** 实测带着这个参数启动，快照文件照样被写了出来。
> 要彻底关掉得用 `-no-snapshot`。

> **别指望删快照能省磁盘。** `snapshots/default_boot/ram.img` 约 4 GB，是客户机的内存镜像
> （大小对应 `hw.ramSize`），**每次开机都会重新分配**，删了立刻长回来。
> 删它只是为了拿到一次干净启动，不是为了空间。

### 9.2 PowerShell 5.1 会把请求体里的中文变成问号

**症状**：用 `Invoke-RestMethod` 发 JSON，服务端收到的中文全是 `?`。典型场景是建 GitHub Release。

**根因**：PowerShell 5.1 的 `Invoke-RestMethod -Body <字符串>` 按 **ASCII** 编码发送，不是 UTF-8。

**修复**：显式转成 UTF-8 字节，并在 `Content-Type` 里声明：

```powershell
$json  = @{ name = '体重日记 v1.0' } | ConvertTo-Json
$bytes = [System.Text.Encoding]::UTF8.GetBytes($json)
Invoke-RestMethod -Uri $url -Method Post -Headers $h `
  -ContentType 'application/json; charset=utf-8' -Body $bytes
```

> **⚠️ 这个坑极难发现：控制台把中文渲染成 `?` 和真乱码长得一模一样。**
> 别靠眼看，直接查码点：
>
> ```powershell
> ($result.name.ToCharArray() | ForEach-Object { 'U+{0:X4}' -f [int]$_ }) -join ' '
> # 正确  U+4F53 U+91CD U+65E5 U+8BB0     （体重日记）
> # 错误  U+003F U+003F U+003F U+003F     （四个问号）
> ```

### 9.3 `git push` 报「读不到用户名」，其实不是凭据丢了

**症状**：

```
error: failed to execute prompt script (exit code 66)
fatal: could not read Username for 'https://github.com': No such file or directory
```

看起来像**凭据过期**或 **credential helper 没配**，非常容易一头扎进去重新登录、重配 GCM。

**根因**：真正的报错藏在助手进程的输出里 ——

```
0 [main] sh (14072) ...: *** fatal error - couldn't create signal pipe, Win32 error 5
1 [main] bash (20968) ...: *** fatal error - couldn't create signal pipe, Win32 error 5
```

Git Credential Manager（`credential.helper = manager`）要起一个 shell 去读 Windows 凭据管理器，
而**受限权限的沙箱不允许创建命名管道**。GCM 起不来 → git 退回交互式索要用户名 → 非交互环境直接失败。

**最容易误判的地方**：`git fetch` 在同一环境下**是好的**（公开仓库拉取不需要认证），
只有 `git push` 失败。于是看起来像「网络没问题，只有认证坏了」，方向完全跑偏。

**诊断**：直接查一次凭据就能复现，看有没有 `signal pipe` 那行：

```powershell
"protocol=https`nhost=github.com`n`n" | git credential fill
# 正常：输出 username=... 与 password=...
# 本坑：fatal error - couldn't create signal pipe, Win32 error 5
```

**解法**（两条任选，都不用去动凭据）：

1. **在 DSH 里给这一条 `git push` 提权一次** —— 让它跑在不再受限的模式下，就能创建命名管道，
   GCM 正常起来。**只需要给这一条命令**，不必切终端、也不必重配任何东西。
2. 或者换到**允许创建命名管道**的普通终端里推送。

顺手建议设 `$env:GIT_TERMINAL_PROMPT=0`：万一 GCM 起不来、退回交互式索要用户名，
**宁可失败也不要卡住** —— 非交互环境里卡住比失败更难查。

受限沙箱内无论重试多少次都不会成功 —— 这不是网络或凭据问题，重试没有意义。
（2026-10 推 `feature/health-connect` 时又踩了一次，按第 1 条一次就过。）

### 9.4 建 GitHub Release：`gh` 不读 git 的代理配置

**症状**：`gh auth login --web` 走到最后一步失败：

```
failed to authenticate via web browser:
Post "https://github.com/login/oauth/access_token": read tcp …: wsarecv:
连接方在一段时间后没有正确答复…
```

看起来像网络不通或授权被拒，**其实都不是**。

**根因**：这台机器访问 GitHub 要走本机代理，而代理**只配在 git 里**：

```
git config --get-regexp proxy
→ http.https://github.com.proxy  http://127.0.0.1:7897
```

`git push` 能通就是因为 git 读这条配置；而 **`gh` 完全不读 git 配置**，
只认 `HTTPS_PROXY` / `HTTP_PROXY` 环境变量 —— 那两个是空的，于是它直连 GitHub。

**解决**：跑 `gh` 之前显式给代理。

```powershell
$env:HTTPS_PROXY = 'http://127.0.0.1:7897'
$env:HTTP_PROXY  = 'http://127.0.0.1:7897'
gh auth login --web --git-protocol https --hostname github.com
```

**为什么这条极难诊断 —— 三个工具全都在骗你**：

| 工具 | 表现 | 真相 |
|---|---|---|
| `Get-NetTCPConnection -LocalPort 7897` | 返回**空**（不报错） | **假阴性**。受限沙箱下端口枚举被挡，代理其实在 LISTENING（`netstat -ano` 看得到） |
| `curl -x http://127.0.0.1:7897 https://…` | `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS` | 与网络无关 —— 受限 shell 里 **Windows 的 TLS 栈（schannel）用不了**。`curl` 与 `Invoke-WebRequest` 都走 schannel，所以都会这么挂 |
| 裸连 `github.com:443` | TCP 握手**成功** | 有迷惑性。SNI 干扰的典型特征就是**握手放行、ClientHello 之后才重置** —— 所以「TCP 能连」不代表 HTTPS 能通 |

**只有两个东西给出可信信号**：

- **`git`** —— 自带 OpenSSL（不走 schannel）且读得到代理配置
- **裸 `TcpClient`** —— 只做 TCP，不碰 TLS

**结论**：判断「代理开没开」别用 `Get-NetTCPConnection`，用 `netstat -ano | findstr :7897`
或裸 `TcpClient`；判断「GitHub 通不通」用 `git ls-remote`（公开仓库不需认证）。
另外 `gh` 的凭据存在 `%APPDATA%\GitHub CLI\hosts.yml`，**也在工作区之外**，所以同样要提权。

> **发布包不进 git。** `dist/` 在 `.gitignore` 里（红线 #6），发版走
> **tag + GitHub Release + APK 作 asset**：`v1.0` 就是这么发的，`v1.1.0-beta.1` 同理。
>
> ⚠️ **测试版必须勾 "Set as a pre-release"** —— GitHub 的 `/releases/latest`
> 只认**非 prerelease、非 draft**，而 README 首页那个「最新版 APK」链接指向它；
> 不勾就会被测试版顶掉。发完可以用
> `https://api.github.com/repos/<owner>/<repo>/releases/latest` 实测确认。

### 9.5 MIUI / HyperOS 默认拦截 `adb shell input`

**症状**：`input tap` / `input keyevent` 静默失效 —— **命令不报错、界面毫无反应**，
看起来像坐标算错了或界面卡住了。加 `2>&1` 才看得到真正的异常：

```
java.lang.SecurityException: Injecting input events requires the caller
(or the source of the instrumentation, if any) to have the INJECT_EVENTS permission.
    at com.android.server.input.InputManagerService.injectInputEventToTarget(…)
```

**根因**：MIUI/HyperOS 默认不授予 shell 注入输入事件的权限。**模拟器上没有这个限制**，
所以本地全绿、真机全挂。

**影响**：**`tools/verify-m2.ps1` 在这类机器上一条断言都跑不了** —— 它整个建立在
`input tap` 上。任何坐标点击驱动的自动化同理。

**解法**：设置 → 更多设置 → 开发者选项 → 打开 **「USB 调试（安全设置）」**
（MIUI 可能要求登录小米账号 + 插卡 + 联网才能开）。**没有 root 绕不过去**：
`sendevent` 要 root，`uiautomator runtest` 要额外装测试 APK。

**在没开这个开关时还能做什么**（真机验证照样有价值）：

| 能力 | 命令 |
|---|---|
| 拉起任意界面 | `am start -n <pkg>/<activity>` |
| 看界面内容与坐标 | `uiautomator dump` + `cat`（坐标是**物理像素**） |
| 截图 | `screencap -p` + `adb pull` |
| 看崩溃与行为 | `logcat -d` |
| 授权/撤销权限 | ❌ **做不到** —— `pm grant` 也被 MIUI 拦（见下） |
| 查组件、权限、状态 | `dumpsys package` / `dumpsys window` |
| 保持常亮防息屏 | `svc power stayon true` |

**顺带一个诊断纪律**：`input` 失效时**不要先怀疑坐标**。先把 `2>&1` 打开看有没有
`SecurityException` —— 这次就是先按坐标错了排查了一圈，白费时间。

> **另一条：`adb` 守护进程在本会话里活不过命令之间。**
> 每次 `pwsh` 调用都要自己 `start-server`，而且**刚起来的 1 秒内设备还没枚举完**。
> 所以每个 adb 步骤都要自带「起服务 → 轮询到可用 → 干活」。
> 判据用 `adb -s <serial> shell echo READY` **而不是** `adb devices` ——
> 实测两者会打架（`devices` 列着它、`shell` 说 `device not found`，反之亦有）。
> 另外**别用 `adb wait-for-device`**：无设备时它无限阻塞，会把整条命令挂死。
