## 1. 产品定位

### 1.1 一句话

给个人用户使用的**纯本地**体重 / 体脂趋势记录工具：**记录一次称重 ≤ 10 秒，看一眼就懂自己处在什么水平、离目标还差多少。**

### 1.2 目标用户与场景

> ⚠️ 这一节是从原始简报**反推**的，没有经过明确确认。若实际目标用户不同，功能和文案都要重新评估。

| 维度 | 判断 | 依据 |
|---|---|---|
| 用户 | 关注体重的普通个人用户，非专业健身人群 | 产品没有训练 / 饮食 / 体态模块 |
| 地域 | 中国用户，公制单位（kg / cm） | 简报为中文；BMI 用「肥胖前期」这类中国标准用词 |
| 使用频率 | 每天 1–2 次，多为晨起空腹 | 「同一天多条记录」「周月取当日最低值」的设计暗示 |
| 单次时长 | 记录 < 10 秒；看趋势 10–30 秒 | 极简布局、无多余步骤 |
| 核心诉求 | 记录 → 看趋势 → 知道自己在什么水平 → 知道离目标多远 | 四张概览卡 + 水平四色条 + 目标进度条 |

### 1.3 设计调性

现代、清新、极简。纯白背景，单一薄荷绿强调色，圆角卡片配极轻阴影，无冗余装饰。

转化为可执行的约束：

- **不做**渐变按钮、彩色插画、emoji、Loading 转圈（用骨架屏替代）
- 一屏之内只有一个强调色，其余全部是灰阶
- 图表不画垂直网格线；X 轴不画刻度线（见 [决策 B16 / B18](04-决策记录.md)）
- 数据为王的区域（图表）优先于装饰

## 2. 核心用户流程

```
首次启动
  └─ 引导填写身高（BMI 的前置条件）+ 可选目标体重
        ↓
日常使用（高频，目标 < 10 秒完成）
  └─ 点右上角 "+" → 底部弹窗填体重（必填）/ 体脂（选填）→ 保存
        ↓
首页即时反馈
  ├─ 概览卡片数字更新
  ├─ 目标进度前进
  ├─ 图表新增数据点
  └─ 历史列表新增一项
        ↓
低频分析（每周 / 每月）
  ├─ 切换 日 / 周 / 月 / 年 / 总 看趋势
  ├─ 点左右箭头平移日期范围
  ├─ 图表内左右滑动查看视口内数据点
  └─ 点「查看更多记录」→ 全量列表（编辑 / 删除）
```

## 4. 数据与隐私

- **纯本地存储**，无网络层、无账号、无上报
- 健康数据属于敏感个人信息，本地存储是隐私成本最低的方案
- 代价：**换机即丢**。因此 P1 的导出 / 备份恢复不是可选项，是这块取舍的兜底
- 添加数据弹窗底部需展示一行说明：「所有数据仅保存在本机」

## 5. 非目标（明确不做）

| 不做 | 原因 |
|---|---|
| 饮食 / 运动 / 卡路里记录 | 本产品只解决体重与体脂趋势 |
| 社交、排行榜、打卡分享 | 与「私密健康数据」定位冲突 |
| 医疗建议、健康风险诊断 | 合规风险，且超出产品能力 |
| 复杂的目标体系（多阶段、期限、里程碑） | v1 只做单值目标，避免过早复杂化 |
| 平板 / 折叠屏专门适配 | 本期只保证竖屏手机 |
| 国际化（多语言） | 中文优先；字符串全部走 `strings.xml`，为将来留口 |

## 6. 验收标准

### 6.1 记录

- [x] 从打开 App 到保存一条体重记录，**操作步数 ≤ 3**（点 + → 输数字 → 保存）
- [x] 体重接受 20–500 kg，超出时保存按钮禁用并给出提示
- [x] 体脂率接受 1–75%，留空可保存
- [x] 身高接受 50–260 cm
- [x] 可选择历史日期时间，但**不能选未来**
- [x] 同一天可记录多条，各自保留时间戳
- [x] 保存后首页所有区域**立即**反映新数据

### 6.2 计算

- [x] BMI = 体重 / (身高/100)²，保留 1 位小数
- [x] 改身高后，**历史所有 BMI 同步重算**
- [x] BMI 分级严格按中国标准：<18.5 较轻 / 18.5–23.9 标准 / 24.0–27.9 超重 / ≥28.0 肥胖
- [x] 四色条滑块位置与所属色块**必须一致**（等宽后的段索引映射，见 [03 技术设计 §3.3](03-技术设计.md)）

### 6.3 图表

- [x] Y 轴恰好 4 个带数字的刻度，且**全部是整数**
- [ ] Y 轴共 13 条水平刻度线（4 主 + 9 次）—— **改为「默认 13 条」**：主步长为整数后，步长 1 时只能分成 5 份（16 条）才是干净的次步长，见 [03 技术设计 §4.4](03-技术设计.md)
- [x] Y 轴范围必须包含目标体重；但目标与数据差值超过区间 30% 时改为只显示方向箭头
- [x] X 轴恰好 5 个日期标签，位置严格四等分
- [x] X 轴**不出现任何刻度线**
- [x] 折线连续平滑，**跨越未记录日期时不出现虚线**
- [x] 空心圆点只出现在真实记录位置
- [x] 目标虚线在折线之下、次刻度之上
- [x] 退化场景不崩不空白：0 条 / 1 条 / 全部数值相同

### 6.4 交互

- [x] 图表内左右滑动 = 滚动视口，**不切换日期范围**
- [x] 切换日期范围**只能**通过左右箭头
- [x] 滑到范围边缘**停住**，不自动翻页 —— 回弹动画未做，是硬停（已在 05-交付计划 M3 记录）
- [x] 纵向滚动页面时，手指落在图表上也能正常滚动页面（手势方向判定）
- [x] 达到目标体重时，目标卡片变绿 + 微动效，**不弹窗打断**

### 6.5 性能与健壮性

- [x] 冷启动到首页可交互 < 1.5 s（中端机）
- [ ] 1000 条记录时图表滑动不掉帧 —— 已验证的是**列表**（Missed Vsync 0）；图表在 1000 点下的滑动性能未单独实测
- [x] 杀进程重进数据不丢
- [x] 数据库表结构变更走 Room Migration，不 `fallbackToDestructiveMigration`

## 7. 术语表

这些词在本项目里有**特定含义**，与日常理解可能不同：

| 术语 | 含义 |
|---|---|
| **最新值** | 时间戳最大的那条记录的值。概览卡片、目标卡片用它 |
| **当日最低值** | 同一天多条记录中体重最小的那条的**整条记录**。周 / 月 / 总视图用它 |
| **水平** | BMI 分级结果，四个等级：较轻 / 标准 / 超重 / 肥胖 |
| **目标线** | 图表中代表目标体重的水平虚线 |
| **目标进度条** | 目标卡片底部细线，展示从「设置目标时的体重」到目标体重的完成度 |
| **指标** | 体重 / BMI / 体脂率三者之一，决定图表 Y 轴画什么 |
| **退化场景** | 数据量为 0 / 1 条，或所有值相同这类会让图表算法除零或范围为零的情况 |

> 「最新值」与「当日最低值」的差异是**有意设计**的，不是 bug，详见 [决策记录 · 冲突 2](04-决策记录.md)。
